# SIH25038 increment 2 — report

Scope: registry reporting UI, structured species and geospatial evidence ingestion, a safe credit lifecycle (disputes; cancellation as a proposal), an automated end-to-end journey, and real-browser, accessibility and mobile checks. Evidence is in `SIH25038_INCREMENT_2_TEST_REPORT.md`; requirement status in `SIH25038_REQUIREMENTS_TRACEABILITY.md`.
This is **not a claim of SIH-readiness.** Scientific validation, drone hardware, SMTP, IPFS and malware-scanner services, mobile-app integration and any on-chain cancellation remain open (below).

## What was built
**Registry reporting (`#/reports`, new for every role).** Filters (project, ecosystem, region, record status, data origin, activity dates, grouping by project, ecosystem, region, month or status). Quantities kept separate and defined on the page: reported and verified records and area; estimated central and conservative tCO₂e (an estimate, not a credit); approved-eligible tonnes (approved is not issued); issued, **transferred** (cumulative movement from the credit-event ledger, not a balance), retired and outstanding. Totals are computed by the database over the same filters (summing grouped rows would double-count projects that appear in several months). Rows are always split by data origin, so illustrative sample data is never added to user-entered data. Loading, empty, error-with-retry and malformed-response states (a reply that fails shape checks shows an error, never figures); a 500-group cap with a warning; CSV download through the authenticated API with the current filters (values beginning `= + - @` are neutralised). Field users only ever receive their own organization's figures (enforced in SQL).

**Geospatial evidence import and species.** A GeoJSON import contract and validator (`services/geo.js`, documented in its header): size, encoding and JSON checks; geometry types; coordinate ranges with a hint when latitude and longitude look swapped; CRS; ring closure, zero area and self-intersection; property types; **containment in the project's configured boundary** (every point must be inside, lines and polygons need at least one vertex inside, partial overlap is a warning). If a project has no boundary, or an unusable one, the result says containment was **not validated** instead of passing or failing the file. `POST /geospatial/validate` is a dry run that stores nothing; `POST /geospatial/import` stores only files that pass: the original bytes with SHA-256 as evidence of the new kind `GEOSPATIAL`, a frozen `geospatial_imports` row (validator version, boundary result, counts, tool and version), the supersede of an earlier version and the audit entry, **in one transaction**. Duplicates are refused; corrections supersede without deleting history; the files are served sandboxed. Counts found in a file are shown to the reviewer next to the collector's declared species as an unreviewed comparison and never change measurements. Structured species per record (`record_species`, locked by trigger once the record leaves draft or revision; audited with before and after; snapshotted at submission into the content hash and anchor, **only when present, so every earlier record's hash is unchanged**); an advisory check compares the species total with the `seedlings_planted` measurement. UI: an import panel on the Evidence page (check without storing, rejected-file report, import) and a species editor plus read-only reviewer view on the record page. This is a file import; no drone is connected and no image analysis exists.

**Credit lifecycle.** Disputes against an issued batch (`credit_disputes`, append-only `credit_dispute_events`, migration 010): raised by reviewers, administrators or involved organizations; reviewed and decided only by an NCCR administrator who is not the person who raised it; valid transitions enforced by the database as well as the service; mandatory reasons; audit entries with actor, reason, record and assessment; notifications. While a dispute is open, under review or **upheld**, the API refuses to start transfers and retirements of the batch (checked before and inside the reservation transaction, for holders and for administrators acting for them) and starts no blockchain operation. **This is a registry control. It does not freeze, cancel or reverse the on-chain token**, and every screen and response says so. Cancellation and a privacy-preserving retirement are specified, implemented as a separate contract and tested, but **not adopted**: see `SIH25038_CREDIT_CANCELLATION_PROPOSAL.md`.

**Journey, browser and recovery.** `backend/tests/journey.test.js` (onboarding to NCCR reporting, with every negative case) and `e2e/` (real Chromium, 58 checks: import and species in the browser, reports and CSV download, dispute dialog focus and Escape, keyboard order, 390 px layout of 18 role-page combinations, axe WCAG 2.1 A/AA on 18 pages). Defects found and fixed along the way, including recovered operations that had lost their transaction hash and a router race, are listed in the test report.

## Deployment impact
- **Two migrations** (009, 010), additive and idempotent; run `npm run db:migrate` (they apply in order). No existing column changed meaning; the one new column is nullable.
- **No contract redeployment** and no change to the deployed ABI.
- **No new required environment variable.** Optional: `GEO_MAX_BYTES` (default 5 MB), `GEO_MAX_FEATURES` (5000), `GEO_MAX_VERTICES` (250000).
- Restore: the `record_species` lock trigger does not interfere with `pg_restore` (PostgreSQL archives create triggers after loading data); the drill proves it with a locked species list in the backup.

## Known limitations and remaining blockers
1. **Scientific validation (blocking for any real credit).** The IPCC Tier 1 method is still pending independent review; the illustrative method uses placeholder parameters. Nothing here is validated carbon accounting.
2. **No on-chain reversal.** Disputes are a registry control that direct on-chain calls bypass (reconciliation detects such a divergence; it cannot prevent it). Adopting cancellation needs the decisions listed in the proposal.
3. **Drone integration** is a file import only; geometry validity and boundary containment do not show that a file's contents are true.
4. **Species** are free text, not checked against a taxonomy.
5. **Android app**: not in this workspace; the PWA is the only mobile client, and mobile checks were emulated in Chromium.
6. **Services not exercised here:** Kubo, ClamAV, SMTP, Pinata; no public-network deployment.
7. Reporting caveats: the estimate column sums each record's current assessment regardless of approval state (a pipeline figure); `transferred` is movement, not a balance; groupings are capped at 500 rows.
8. **CI and an application Dockerfile are still absent.** The blockchain dev toolchain has 44 audit findings (not deployed).
9. An upheld dispute keeps the hold indefinitely; there is no release path other than a future on-chain remedy or an administrator process that does not yet exist.

## Single highest-priority next task
Obtain an independent scientific review of the methodology parameters and decide the cancellation policy (the proposal's open questions). Everything technical about issuing and tracing credits is now tested end to end, but without a validated methodology and a remedy for invalid credits the system cannot responsibly issue real ones.
